# Taste Import

Taste 是部署在自己服务器上的单人视觉参考库：一个**内容组**是一份参考，组里放同一来源、会被一起看的素材；分类靠标签，搜索匹配**标题、备注和标签**，不匹配文件名。

CLI 是本仓库的 `app/bin/taste`（本 Skill 目录上两级；未链接到 PATH 时用完整路径，下文写作 `taste`）。先跑 `taste doctor` 检查连接与鉴权；缺配置、断线或凭据错误时报告问题。客户端只连接服务器；连接配置见 `taste config`，修复后再继续。所有写入都走 CLI，不碰 Runtime 里的文件与 SQLite。

## 导入流程

1. **逐张看内容。** 读取每个文件的画面；GIF 首帧常为空白，取中间帧判断；HEIC 可直接导入（自动转 JPEG）。与设计参考无关的私人照片（如生活随手拍）先列给用户确认去留。
   ✓ 每个文件都有一句基于画面的内容描述，没有按文件名猜测
2. **拉取现有词汇与分组。** `taste tags` 取正在使用的标签；`taste list` 看已有组的标题与备注。
3. **判断分组。** 同一来源（同一产品的多屏、同一作者的作品——即使分属不同系列、同一段视频的截帧、同一份材料的多页）且会被一起看的素材放一组；只是主题或风格相近的各自成组，靠标签关联。画面水印（如小红书号）相同即视为同一来源。本批次内同源的一起导入；库里已有同源组时，用 `taste search "<来源关键词>"` 或 `taste list` 定位，再加进该组。
   ✓ 每个文件都已判定为「新建组」或「加入组 <item-id>」
4. **命名。** 标题用「主体·特征」式中文短语，画面里能读出的产品名、品牌名、作者系列原样保留（如「CRM销售仪表盘·气泡图与线索卡片」「Teenage Engineering硬件」）。导入前把源文件重命名为 `<标题>.<扩展名>`，让素材名同样可读；多张同组时用各自的「主体·特征」命名文件，组标题取共同主体；单张成组时素材名与组标题相同。已入库的素材用 `taste asset rename <asset-id> <名称>` 改名，扩展名自动保留。
5. **打标签。** 每组恰好 1 个**形态**标签，再加 0–2 个手法标签、0–1 个载体标签，优先复用 `taste tags` 里已有的词，已有词都不贴切时才新造。形态按「从它身上学什么」选，不按「它是什么东西」选：从 `taste forms` 输出的当前清单中选（含每个形态看什么的说明）；现有形态都不贴切时，向用户确认后 `taste form add <形态> --desc "<看什么>"` 新增，不再手改任何词表文件。
   - 手法说怎么做的，如手绘、手写、复古、拼贴、像素、等距、拟物、玻璃拟态、暗色、极简、漫画、水彩、东方、3D、摄影、AI生成。载体说用在哪，界面类如日程、定价、输入框、导航、工作流、终端、对话、数据、财务、任务；平面类如海报、幻灯片、杂志、票据、邮票、简历、折页、明信片、品牌，其中海报在版式和画面里都可以挂。
   - 只说画的是什么的题材词（自然、科普、人物之类）不打，找它靠标题和备注里的看点；用户会按它找的主题例外，目前是 AI 和户型。
   - 易混形态这样判：版式和画面，遮住所有文字后仍值得留的归画面，否则归版式；版式和图解，靠排得好的归版式，靠讲得清的归图解；界面和版式，可操作的软件界面归界面类形态，只为排版收的截图（发布会、视频截帧、文档页）归版式。

6. **写备注。** 第一行写「看点：<一句话>」，说这组具体值得学什么（配色、字怎么排、构图、笔触），不复述标题；画面水印或用户提供的信息里能读出来源时，第二行写「来源：<平台> <账号或号码>」（如「来源：小红书号 1499006949」），读不出就不写这行。
   ✓ 每组备注都能回答「为什么收它」
7. **执行导入。**
   - 新建组：`taste import <文件...> --title "<组标题>" --tag <形态> --tag <标签> --note $'看点：...\n来源：...'`
   - 加入已有组：`taste asset add <item-id> <文件...>`，来源或标签需要补充时再 `taste update <item-id> --note ... --tags "形态,标签"`
   - 导入默认**移动**：成功后源文件被删除。用户要求保留原件时加 `--copy`。
   ✓ 每条命令返回了 item；「重复文件已存在」的文件源文件仍在原处，列给用户决定是否删除
8. **核对。** `taste list` 确认新组的标题、标签、素材数与计划一致，源目录只剩被拒绝或待确认的文件。

## 整理已有内容

拆分或合并现有组时沿用第 3–6 步的判据：`taste create --title ... --tag ...` 建组，`taste asset move <asset-id> <item-id>` 移动素材（组被移空后自动删除），`taste update` 改标题、标签、备注，`taste item before <item-id> <目标 item-id>` 把改了形态的组移到对应形态区段，`taste item reorder <全部 item-id>` 需要传入库里全部组的完整顺序。首页按 `taste forms` 的清单顺序排列。多素材组用 `taste layout` 排成顶端对齐、等高（400）、间距 40 的行，素材多时均分成几行，宽度按裁切后的宽高比计算。批量改动前先给用户看整理方案，确认后执行。

## 交付

汇报导入的组数与素材数、新建和加入的组、新造的标签、被拒绝或待确认的文件及原因。自动去边裁切看起来不对的素材，用 `taste asset crop <asset-id> off` 关闭，`auto` 恢复。
