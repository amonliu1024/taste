# Taste Import

Taste 是本机、单人的视觉参考库：一个**内容组**是一份参考，组里放同一来源、会被一起看的素材；分类靠标签，搜索只匹配**备注和标签**，不匹配标题和文件名。

CLI 是本仓库的 `app/bin/taste`（本 Skill 目录上两级；未链接到 PATH 时用完整路径，下文写作 `taste`）。先跑 `taste status`，未运行时 `taste start`。所有写入都走 CLI，不碰 `~/.local/share/taste` 里的文件与 SQLite。

## 导入流程

1. **逐张看内容。** 读取每个文件的画面；GIF 首帧常为空白，取中间帧判断；HEIC 可直接导入（自动转 JPEG）。与设计参考无关的私人照片（如生活随手拍）先列给用户确认去留。
   ✓ 每个文件都有一句基于画面的内容描述，没有按文件名猜测
2. **拉取现有词汇与分组。** `taste tags` 取正在使用的标签；`taste list` 看已有组的标题与备注。
3. **判断分组。** 同一来源（同一产品的多屏、同一作者的作品——即使分属不同系列、同一段视频的截帧、同一份材料的多页）且会被一起看的素材放一组；只是主题或风格相近的各自成组，靠标签关联。画面水印（如小红书号）相同即视为同一来源。本批次内同源的一起导入；库里已有同源组时，用 `taste search "<来源关键词>"` 或 `taste list` 定位，再加进该组。
   ✓ 每个文件都已判定为「新建组」或「加入组 <item-id>」
4. **命名。** 标题用「主体·特征」式中文短语，画面里能读出的产品名、品牌名、作者系列原样保留（如「CRM销售仪表盘·气泡图与线索卡片」「Teenage Engineering硬件」）。导入前把源文件重命名为 `<标题>.<扩展名>`，让素材名同样可读；多张同组时用各自的「主体·特征」命名文件，组标题取共同主体；单张成组时素材名与组标题相同。已入库的素材用 `taste asset rename <asset-id> <名称>` 改名，扩展名自动保留。
5. **打标签。** 每组恰好 1 个**形态**标签，再加 0–2 个风格或题材标签，优先复用 `taste tags` 里已有的词，已有词都不贴切时才新造。形态从下表中选：

   | 形态 | 收什么 |
   |---|---|
   | 网页 | 官网、落地页、作品集、网站内页 |
   | App | 手机界面、应用商店截图 |
   | 软件界面 | 桌面或 Web 工具界面：编辑器、聊天工作台、终端、日历应用 |
   | 仪表盘 | B 端后台、数据看板、管理系统 |
   | 组件 | 单个控件、卡片、菜单、输入框、动效片段 |
   | 图解 | 概念图、信息图、架构图、流程图、学习路线 |
   | 演示 | PPT、幻灯片、长图演示 |
   | 海报 | 海报、平面版式、折页、壁纸 |
   | 插画 | 插画、角色、抽象画、游戏画面、等距场景 |
   | 字体 | 字体样张、字效、标题字设计 |
   | 图标 | 图标集、符号体系 |
   | 摄影 | 实拍、人像、产品摄影、视频截帧 |
   | 工业设计 | 硬件、实体产品设计 |
   | 实物素材 | 票据、单据、号码牌、包装等实物 |

6. **记录来源。** 画面水印或用户提供的信息里能读出来源时，备注写「来源：<平台> <账号或号码>」（如「来源：小红书号 1499006949」）；读不出就留空。
7. **执行导入。**
   - 新建组：`taste import <文件...> --title "<组标题>" --tag <形态> --tag <标签> --note "<来源>"`
   - 加入已有组：`taste asset add <item-id> <文件...>`，来源或标签需要补充时再 `taste update <item-id> --note ... --tags "形态,标签"`
   - 导入默认**移动**：成功后源文件被删除。用户要求保留原件时加 `--copy`。
   ✓ 每条命令返回了 item；「重复文件已存在」的文件源文件仍在原处，列给用户决定是否删除
8. **核对。** `taste list` 确认新组的标题、标签、素材数与计划一致，源目录只剩被拒绝或待确认的文件。

## 整理已有内容

拆分或合并现有组时沿用第 3–6 步的判据：`taste create --title ... --tag ...` 建组，`taste asset move <asset-id> <item-id>` 移动素材（组被移空后自动删除），`taste update` 改标题、标签、备注，`taste item before <item-id> <目标 item-id>` 把改了形态的组移到对应形态区段，`taste item reorder <全部 item-id>` 需要传入库里全部组的完整顺序。首页按 14 个形态的表格顺序排列。多素材组用 `taste layout` 排成顶端对齐、等高（400）、间距 40 的行，素材多时均分成几行，宽度按裁切后的宽高比计算。批量改动前先给用户看整理方案，确认后执行。

## 交付

汇报导入的组数与素材数、新建和加入的组、新造的标签、被拒绝或待确认的文件及原因。自动去边裁切看起来不对的素材，用 `taste asset crop <asset-id> off` 关闭，`auto` 恢复。
